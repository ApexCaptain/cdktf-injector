# 이슈 일정 (`issues/schedule.md`)

`issues/active/`가 SSOT. `issues/schedule.md`는 열린 이슈 중 **아직 할 일·추후 확인이 남은 것**의 인덱스다. 날짜·수용 기준·재현은 이슈 본문에만 적는다.

## 언제 보나

- 이슈를 만들거나, 상태·재검토일·트리거를 바꾸거나, `issues/resolved`로 옮길 때 — **같은 턴에** schedule도 맞춘다
- 이슈 관련 작업을 시작하기 전 — `issues/schedule.md`를 읽고 **오늘 날짜(KST)** 와 대조한다. 기한이 왔거나 지났으면 작업 들어가기 전에 한 줄로 알린다
- 사용자가 일정·다음에 할 일·재검토를 물을 때

무관한 원라이너·질문만 있는 대화에서는 스케줄을 건드리지 않는다. 기한 도래는 **알리고 확인**한다. 사용자 요청 없이 일정 때문에 이슈를 아카이브하거나 코드를 바꾸지 않는다.

## 동기화

일정표만 단독으로 고치지 않는다. 날짜를 지어내지 않는다. 이슈에 날짜가 없으면 **날짜 없음 (트리거 대기)** 에 둔다.

| 이슈 변화 | schedule |
|---|---|
| 재검토일·확인일·트리거가 생긴 열린 이슈 | 행 추가·갱신 |
| 날짜 있음 / 없음 | **달력** / **날짜 없음 (트리거 대기)** |
| `issues/resolved`로 이동, 또는 이 레포에서 할 일 없음 | 해당 행 삭제 |
| 날짜·상태가 바뀜 | 이슈 메타와 동일하게 |

할 일은 한 줄. 링크는 `active/YYYY-MM-DD-slug.md` (`issues/schedule.md` 기준 상대 경로). 상태 칸은 이슈 메타 `상태`와 같게.

## 하지 않을 것

- schedule을 이슈 SSOT로 쓰지 않는다
- 해결된 항목을 일정에 남기지 않는다
- 이슈 본문과 어긋난 날짜·상태를 일정에만 적지 않는다
