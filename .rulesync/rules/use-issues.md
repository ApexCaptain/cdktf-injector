# 이슈 문서 (`issues/active` → `issues/resolved`)

이 레포의 이슈 SSOT는 GitHub Issue가 아니라 마크다운이다. `docs/`는 TypeDoc 산출물이므로 이슈를 두지 않는다.

| 상태 | 위치 |
|------|------|
| 열림 (조사·진행·완화·후속 남음) | `issues/active/` |
| 닫힘 (이 레포에서 할 일 없음) | `issues/resolved/` |

관련 작업 시작 전 두 디렉터리를 검색한다. 같은 주제면 **기존 파일을 갱신**하고 새 파일을 만들지 않는다. 재검토일·확인 트리거가 있는 열린 이슈는 `issues/schedule.md`에도 올린다 (규칙: `use-issues-schedule`).

## 언제 쓰는가

- 사용자가 이슈 문서화·기록·아카이브를 요청할 때
- 원인·재현·결정이 세션을 넘어 남아야 할 때
- 같은 턴에 고친 원라이너, 질문만 있는 대화, 이미 `issues/resolved`에 있는 건은 쓰지 않는다

## 파일 이름

`issues/active/YYYY-MM-DD-kebab-slug.md`

- 날짜는 **등록일**(최초 작성일). 해결돼도 파일명을 바꾸지 않는다
- slug는 영어 소문자·숫자·하이픈. 제목은 한국어
- 같은 날 다른 이슈는 slug로 구분한다

## 작성

본문은 한국어, 평문. 시크릿·자격 증명·토큰을 넣지 않는다. 나중에 이어서 할 수 있을 만큼만 — 소설 금지.

```markdown
# <한국어 제목 — 증상 또는 결정>

| 항목 | 내용 |
|------|------|
| **등록일** | YYYY-MM-DD |
| **영역** | 패키지·서비스·노드 등 대상 |
| **관련 코드** | 경로 (없으면 생략) |
| **상태** | **조사중** / **진행중** / **완화** / **적용** / **보류** — 한 줄 보충 OK |

## 배경
## 문제
## 타임라인

| 일시 | 내용 |
|------|------|
| YYYY-MM-DD | 등록 |
```

필수: 제목, 메타(`등록일`·`상태`·대상), 배경 또는 증상, 타임라인.

종류에 따라 추가한다. 해당 없으면 섹션을 만들지 않는다.

| 종류 | 추가 섹션 |
|------|-----------|
| 장애·버그 | 증상, 재현, 원인, 조치, 관련 링크 |
| 설계·도입 | 현재 상태, 목표, 접근 비교, 추천, 수용 기준, 범위 밖 |
| 조사·구매 | 실측, 결론, 체크리스트 |

메타 키는 대상에 맞게 늘려도 된다 (`서비스`, `스택`, `발생` 등). **`상태`와 날짜는 유지.**

규칙:

- 증거(로그·명령·링크)는 짧게. 긴 로그 전문 금지
- 가설은 가설이라고 쓰고, 배제한 가설은 표로 남긴다
- 선택지가 둘 이상이면 비교표 + **추천**을 적는다
- 수용 기준은 체크박스. 범위 밖은 후속 이슈로 분리한다고 명시한다
- 코드·설정 인용은 경로를 포함한다

## 갱신

같은 이슈는 같은 파일에 이어서 쓴다.

- 메타 `상태`를 현재에 맞게 고친다
- 타임라인은 **끝에만 append**. 과거 행을 고치거나 지우지 않는다
- 조치가 바뀌면 “현재” 섹션을 갱신하고, 이전 조치는 남긴다 (덮어쓰기 금지)
- 재검토일·확인 트리거·상태가 바뀌면 `issues/schedule.md`를 같은 턴에 맞춘다

## 아카이브 (해결)

이 레포에서 더 할 일이 없을 때만 옮긴다. **완화·upstream 대기·후속 체크가 남아 있으면 `issues/active`에 둔다.** 체크박스가 다 채워져도 사용자가 닫기 전이면 옮기지 않는다. 사용자가 “해결·아카이브·닫기”를 말하면 옮긴다.

1. 메타 `상태`를 **해결**로 바꾸고 **해결일**을 추가한다
2. 짧으면 타임라인 한 줄로 충분. 길면 `## 해결 요약`을 메타 바로 아래에 추가한다
3. 조사 본문은 역사 기록으로 유지한다. 삭제·전면 재작성 금지
4. `issues/active/<file>` → `issues/resolved/<file>` 로 이동 (파일명 유지)
5. `issues/resolved/`가 없으면 만든다
6. `issues/schedule.md`에서 해당 행을 지운다

## 하지 않을 것

- `issues/active`·`issues/resolved` 밖(`docs/`, `tmp/`, 채팅 전용, 임의 경로)에 이슈 SSOT를 만들지 않는다
- 해결 파일을 `issues/active`에 남기거나, 열린 이슈를 `issues/resolved`에 두지 않는다
- 사용자 요청 없이 기존 이슈를 삭제하지 않는다
